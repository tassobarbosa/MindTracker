# Implementation Plan: MindTracker Core App

**Branch**: `001-mindtracker-core` | **Date**: 2026-05-25 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-mindtracker-core/spec.md`

## Summary

Build a local-first Progressive Web App that lets a single user log daily headache intensity, work environment, and notes — then browse history and spot correlations via a timeline and analytics charts. The full stack is: TypeScript strict + React 18 (Vite) + shadcn/ui + Zustand + Dexie.js (IndexedDB) + Recharts + React Hook Form / Zod + date-fns + Vite PWA, as mandated by the constitution. Components are split into feature-scoped folders (`entry/`, `timeline/`, `analytics/`, `layout/`, `ui/`) to maximise independent extensibility.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode)

**Primary Dependencies**: React 18, Vite 5, shadcn/ui (Radix UI + Tailwind CSS), Zustand 5, Dexie.js 4, Recharts 2, React Hook Form 7 + Zod 3, date-fns 3, React Router v6, Vite PWA plugin (Workbox)

**Storage**: IndexedDB via Dexie.js — single object store `dailyEntries`, primary key `dateKey` (YYYY-MM-DD), versioned schema for safe future field additions

**Testing**: Vitest + React Testing Library + MSW; `fake-indexeddb` for Dexie unit tests; co-located `*.test.ts(x)` files per module

**Target Platform**: Modern browsers (Chrome 100+, Safari 15.4+, Firefox 110+) as a PWA; mobile-first responsive layout (min 320px)

**Project Type**: Progressive Web App (single-user, local-first)

**Performance Goals**: Interactive within 2 s on mid-range mobile; daily entry flow completable in ≤30 s; smooth timeline scrolling up to 730 entries

**Constraints**: Offline-capable for all read operations (PWA service-worker); no backend server; no user authentication; WCAG 2.1 AA accessible markup

**Scale/Scope**: 1 user; ~730 entries per 2 years; 4 screens (entry, timeline, analytics, layout shell); 3 charts

**Structure Decision**: Feature-scoped component folders. Each folder (`entry/`, `timeline/`, `analytics/`, `layout/`, `ui/`) is an independently portable vertical slice — swapping or extending one area requires no changes to sibling folders. Pages are intentionally thin; all business logic lives in stores, db, hooks, or lib. Co-located tests eliminate the need for a mirrored test tree.
